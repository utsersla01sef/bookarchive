# 费曼式学习计划生成器

把任意「主题/知识/技术/领域」转化为一套**可迁移的交互式学习计划**：费曼启发提问 → 高屋建瓴定位 → 多角度理解 → 是什么/不是什么 → 前沿连接 → 练习 → 打标递推 → 每日动态提醒。

## 触发场景

- 用户想为某个新主题制定学习计划
- 用户提到「费曼式」「学习计划」「高屋建瓴」「打标递推」「每日提醒」等
- 用户想把学习的方法迁移到其他工具 / 其他知识领域

## 计划文件固定结构

用 YAML frontmatter + Markdown 正文，正文必含以下章节（顺序可微调）：

```
---
kind: plan
状态: 进行中
创建: YYYY-MM-DD
标签: [主题关键词]
---
# <主题> · 费曼式学习

> 一句话说明目标 + 可迁移性（能复用到哪些同类知识）。

## 方法论        ← 见下方「核心机制」
## 课程地图      ← 分阶段 + 编号节点（N0, N1, ...）
## 贯穿线索      ← 工具箱 / 架构对照 / 迁移模板 / 交叉前沿
## 资源清单      ← 官方教程、公开数据集、竞赛、参考实现
## 里程碑        ← 每节点一个 `- [ ] Nx 名称`
## 进度日志      ← `日期 | 节点 | 状态 | 一句话收获`
## 误解本        ← `日期 | 我曾以为 | 实际是 | 来源节点`
## 复盘          ← 空占位，学完阶段性回填
```

## 核心机制（写进「方法论」章节）

1. **节点状态机**：⬜未开始 → 🟨进行中 → 🟩已完成。完成即打标（日期写进进度日志），自动递推下一节点（从「里程碑」找第一个未勾选的 `[ ]`）。
2. **「完全理解」三准则**（费曼测试，全过才打标）：
   - 能用自己的话向外行讲清
   - 能说出它**不是什么**（举反例、指出常见误解）
   - 能迁移：换数据/换任务/换场景仍会用
3. **节点六要素模板**（每个节点讲解时套用）：
   🗺️ 高屋建瓴定位（在全景知识图谱中的位置 + 前置依赖 + 通向哪里）
   🎭 多角度理解（至少两个视角，如「概念视角 / 工程实现视角」）
   ✅ 是什么 / ❌ 不是什么（误解清单）
   🔭 前沿连接（对应最新论文/设计，附来源）
   ✍️ 练习（概念题 + 代码题 + 实战题）
   🚦 完成判据
4. **间隔复习队列**：已完成节点在第 1 / 3 / 7 天进入每日提醒的快速回顾（一句话复述核心 + 一个「不是什么」）。
5. **误解本**：持续收集「不是什么」中踩过的坑。
6. **前沿雷达**：每周查一次该领域最新进展（arXiv / 权威综述）。

## 四段式教学流程（每个节点内部）

费曼式对话按四段推进，**先问后讲、直觉优先、公式随后**：

1. **① 提问启动**：先抛 2-3 个无需专业知识的直觉问题，让用户用「我觉得…」回答；用用户的直觉做切入点。
2. **② 概念探索**：结合用户回答逐层展开，先给物理/直觉图像，再落到符号。
3. **③ 练习验证**：布置分层练习（基础→迁移→实战），让用户写出推导/步骤或卡点。
4. **④ 思考扩展**：留 1 个桥接下一节点的思考题。

规则：**始终先诊断用户的回答再讲**，不一次性倾倒全部内容；每段结尾请用户回复或回复「【Nx】开始」再推进。

## 迁移学习模板（贯穿线索）

学任何新主题/新模型的五步，写进计划作为可复用的「迁移模板」：

1. 它的基本单元/对象是什么（词 / 句子 / 样本 的隐喻）
2. 它的核心方法 / 预训练任务是什么、为什么这样设计
3. 它能做什么、**不能做什么**（零样本边界）
4. 跑一个最小基线对比（避免被 SOTA 叙事带偏）
5. 写「是什么 / 不是什么」卡片

## 学习记录规范（会话日志）

每次会话/每节点登记学习记录，四要素缺一不可：

1. **学习者原话回答**：引号引用，不改写；
2. **真实评价**：✓全对 / ◐部分对（标明哪对哪偏）/ ✗错（错在哪），不许只打勾不评价；
3. **学习者主动提问**：单独标注为「深挖问答」，连同解答要点一并记录；
4. **错误清单**：所有 ◐/✗ 单独成节（`节点 | 原话 | 错在哪 | 正解`），供间隔复习抽问回溯。

## 贯穿线索执行检查（每轮必做）

计划中的「贯穿线索」（工具箱 / 架构对照 / 迁移模板 / 交叉前沿等）容易在逐节点推进中被遗忘。**每一轮教学开始前与节点打标时**：

1. 重读计划的「贯穿线索」章节，列出本节点应落实的线索；
2. 在讲解/练习中显式落实（如：工具箱在该节点的 just-in-time 内容、架构对照表该补的行）；
3. 未落实的线索不得静默跳过——要么本轮补上，要么在进度日志登记「线索 X 延至 Ny」并写明原因；
4. 打标时自查：本节点六要素中「前沿连接」与线索是否对应。

## 每日动态提醒（定时任务）

为计划创建一条每天固定时刻（如 09:00）的定时任务，其 message 指令需包含：

1. 读取计划文件，定位「里程碑」第一个未勾选节点作为当前节点；全部勾选则提示结课并结束。
2. 从「进度日志」按完成日期计算第 1/3/7 天的复习队列。
3. 生成提醒：当前节点 + 课程地图位置（前置→当前→去向）+ 一个费曼式启动问题 + 今日建议动作 + 复习队列。
4. 若当前节点停留超 7 天，提示卡点并建议拆分任务。
5. 用中文、≤300 字、不修改计划文件本身。

## 约束

- 计划写好后同步到用户指定的主目录（如知识库），以及工作副本。
- 打标/进度变更后，两端文件保持一致。
- 保留「来源存疑则标注，结论以权威资料为准」类声明，尤其是大模型生成内容。
